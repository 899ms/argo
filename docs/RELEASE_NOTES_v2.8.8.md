相对 v2.8.7 的改进：修复两个真实用户报告的问题——按文档推荐名配置密钥后引擎静默失效（issue #12）、抓取链不走代理导致需代理站点必然失败（issue #13）；搜索源 218 → 220；新增「直答」与「网页观察」两个子命令。

## 修复（以前不行、现在能行）

- **密钥别名静默失效（#12）**：以前，按文档推荐的新名（如 `ARGO_EXA_API_KEY`）配置密钥，状态显示就绪、引擎却永远返回 0 条且不报错——用户会怀疑自己的密钥有问题。根因是部分专用引擎只认不带前缀的旧名，状态层与执行层各说各话。现在 16 处同类读取全部统一走别名链，推荐名/旧名任一就绪都出结果，缺 key 显式报错；新增源码级一致性门禁防复发。
- **抓取链不走代理（#13）**：以前，需要代理才能访问的站点（如 GitHub 网页）抓取必然挂满 60 秒预算后失败，且显式设置 `HTTP_PROXY`/`HTTPS_PROXY` 也不生效。现在新增统一出口调度层：`ARGO_PROXY` 环境变量、config 按域规则、标准代理环境变量三条路都生效，`NO_PROXY` 全程尊重；GitHub 网页抓取实测成功。

## 新增能力

- **parallel_free 引擎（免密钥）**：Parallel 官方免费搜索端点（无账号、无 key），长摘录自带正文、多数场景省一次抓取；与按量计费的 parallel 通道分立，日常做兜底补位。搜索源 218 → 220。
- **seltz 引擎**：2026 年新兴的 agent 搜索（注册赠 2 万次），响应自带正文摘录。
- **`argo answer`**：直答——带引用的合成答案（Seltz 通道），置信口径=引用数+唯一域名数，上游不造模拟分数。
- **`argo watch`**：网页观察模式——本地快照 + 内容指纹变化检测，抓取失败不伪造结果；`argo watch check --json` 可直接挂 cron。
- **抓取链新增免费云渲染级**：Parallel 免费端点渲染 + 正文提取（markdown），jina 阅读器之后的免浏览器路径。

## 默认关闭功能的打开方式

- 代理默认跟随标准环境变量，什么都不配即为原行为；显式指定用 `ARGO_PROXY=http://127.0.0.1:7890`，或在 config.yaml `network.proxy` 按域分流（必须代理的域配 URL、直连更优的域配 `"direct"`，注释里有三档环境模板）。
- parallel_free 无需配置，自动参与兜底补位；`ARGO_FETCH_PARALLEL=0` 可关闭该抓取级。
- seltz 需在 `~/.config/argo/env` 写入 `SELTZ_API_KEY`。
- 观察模式：`argo watch add <url>` 建快照，cron 里跑 `argo watch check --json`。

## 相关依赖与已知边界

- seltz 中文覆盖未验证，中文查询暂不路由到它；其免费端点无官方配额承诺，已按低优先级保守看管。
