# 批次六_失败分型与节流_2026-09-12

相对 v2.8.6 的改进。四项能力落地 + 一条新命令 + 一个新引擎，全部已实施并过门禁（pytest 1481 绿 / offline 126:0 / live 冒烟与收录门禁 pass）。

## 一、失败分型：新增 blocked（被拦截）与 rate_limited（限流）

此前引擎失败归为四类（dependency / auth / upstream / network），两处失真：

- 429 限流没有归属（落 unknown 或 error），源端在说「慢点来」，引擎本身是好的；
- 反爬拦截没有归属：HTML 引擎的拦截页命中走「静默返回空」路径，没有错误文本，
  在聚合层伪装成 no-results——被封的引擎会被当成持续故障累计到 auto-disable，
  这是封错人：引擎实现没有问题，换客户端形态或等源站策略变化即可恢复。

落地内容：

- `engine_failure.py`：分类扩展为六类。403 的歧义仲裁——纯 403 仍是 auth（API
  场景下最常见含义），403 叠加拦截页特征判 blocked；页面级反爬检测显式命中
  （anti_bot=True）是强证据，先于状态码推断；`members-only` 之类 auth 语义
  永远先于封锁特征。不知道就返回 unknown 的纪律不变。
- `engines_base.py`：新增失败归因寄存器（进程内引擎 → 最近一次归因），
  归因在失败现场写入（唯一能同时拿到引擎名、状态码、响应体的位置），
  聚合层读后即清。`_http_get_raw` 按状态码写入归因（429/503 → rate_limited、
  403+特征 → blocked、401 → auth、连接失败 → network）。
- `search.py`：outcome 分类新增 blocked；归因寄存器合入 outcome（静默失败路径
  的真实状态对 `--json` 可观测面可见）。
- `circuit_breaker.py`：record_failure 新增 blocked / rate-limited 两类——与
  empty 同语义：60s 短冷却、不累计 opens、永不驱动 auto-disable。status() 输出
  补 last_kind 字段（引擎健康面板可看最近失败类型）。

## 二、域族节流：并发桶 + 最小间隔

配额表管「一天能用多少次」，管不了「这一秒打了多少次」。fan-out 并行时同一
引擎被多个工作线程同时命中，聚合起来对源站形成密集连击，换来 429 与封锁。

落地内容（`http_client.py`）：

- 域族归一表：同一家源站的多个域名（主站/API/CDN，如 x.com/twimg.com、
  bilibili.com/hdslb.com）共享同一个节流桶——站点感受到的压力来自「这一家」，
  按域名分桶会让主站限流而 CDN 域继续冲锋。首张表覆盖 18 组高频敏感域族。
- 双层节流：并发信号量（同时在途请求上限）+ 相邻请求最小发起间隔。
  二者缺一不可：只有并发上限、间隔为 0，请求会瞬间齐发；只有间隔、没有
  并发上限，前序请求变慢时在途照样堆积。
- 只对声明组生效：免费 API 有明确配额契约，不做全局节流（零开销直通）。
- 引擎 spec 可显式覆盖：`max_concurrency` / `min_interval_ms` 两字段，声明即
  契约（显式声明不限流也生效）。桶键 = (组名, 参数)，个别引擎用更紧参数时
  自成桶，与组内其余引擎互不干扰。
- 节流包住整个重试循环：重试同样占用源站并发名额。

## 三、归档凭证脱敏：写入时生效

`_public_payload` 此前只删整个字段（headers/cookie）；URL 查询串里嵌的密钥
（很多引擎把 key 放 query）与正文里的凭证会原样入盘，归档文件本身成为泄漏面。

落地内容（`archive_run.py`）：

- `redact_secrets()`：URL 查询串密钥改写 [REDACTED]（23 个敏感参数名，含
  SESSDATA/bili_jct/d_c0 等中文平台凭证）、Bearer 头、家目录路径改 ~。
- 脱敏发生在写入时而非导出时——密钥一旦明文落盘就已泄漏，事后清理依赖
  「有人记得在出口调用」，不可靠。覆盖 envelope 与三类 jsonl 全部下游数据。
- 按类别正则实现、逐类测试锁定；宁可多脱一个无害参数，不可漏一个真密钥。

## 四、批量预检：argo preflight 新命令

批量抓取最贵的失败方式是「跑到一半才知道一半拿不到」。预检把可预判的失败
挪到开工前：

```
argo preflight "url1" "url2" ...     # 纯本地规则，零网络
argo preflight --file urls.txt --probe   # 联网探测存活（404/410 判死）
```

条目四类：unsupported（非 http(s) URL）/ needs_auth（登录墙域，唯一用户可
行动类）/ already_have（本地归档已有）/ not_found（探测已死）。结论三档
go / go_with_skips / stop。纪律：不探测不臆测——探测不到不等于不存在，
连不上不产生「已死」判定；预检只做判定不做抓取，与执行器分离。

## 五、新引擎：twitter_syndication（X 单条推文，免登录）

X 网页与官方 API 对未登录请求一律拒绝；syndication 通道是面向第三方网页
嵌入的公开接口，访问凭证由推文 ID 本地推导（公开推导式，无需任何账号），
常年可用、零 key。这是 X 单条内容的第二条通道，与 twitter（搜索型）互补。

- 查询词：推文 URL（x.com / twitter.com / 分享链接参数）或裸 ID；拿它搜
  关键词时诚实返回空（无搜索端点，不伪造结果）。
- spec 用 quality_queries 自述质量集（推文 URL），避免默认关键词探针对
  抽取型引擎误判零结果。
- 收录门禁：health + quality 双阶段 pass（q=1.0，live 实测 519ms）。

## 回归风险与回退

- 节流只影响声明域族（18 组），未声明域名零改动；ARGO_ENGINE_HTTP_CLIENT=0
  回退路径不变。
- 熔断新 kind 只放宽（blocked/rate-limited 不再驱动 auto-disable），不影响
  error/timeout 既有行为。
- 归档脱敏仅收紧输出（多脱不漏），读取端 schema 不变。
