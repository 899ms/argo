# Argo v2.8.6 发布说明

**版本**：2.8.6（相对 2.8.5）
**日期**：2026-09-07
**主题**：搜索更快更准、长尾拖尾大幅收敛；知乎三源语义分工并解锁全部额度；新源接入从「改多处配置」变成「声明一次」，死源由门禁自动显形。

## 主要改进

### 1. 搜索速度

- **首引擎宽限窗竞速（hedged racing）**：主引擎 2 秒宽限窗内出结果且合格 → 只付 1 次调用（旧竞速固定双发，成本回退消除）；窗内未完成才补发次引擎并行赛跑，先合格者赢。被弃置的慢线程改为 daemon 管理，CLI 单发不再被拖住退出。
- **地理查询拖尾 −56%**（12.4s→5.5s）：OSM 的 6s 超时声明此前是死配置（被调用方超时整体覆盖 + YAML 同名键静默覆盖 + 引擎内重试翻倍，三层叠加），修复后为硬上限；引擎内连接级重试移除，重试语义上移到编排层（换引擎/熔断/救援链各司其职）。
- **fast 模式 6 秒总墙钟预算对并行路径同样生效**：deadline 之后不再起新引擎、等待窗口按剩余预算收口，与串行路径同语义。

### 2. 准确率

- **live 多语言金标命中率 69%→100%**，此后连续多轮保持 100%（域命中/选择命中/零污染）：实体型引擎查询规范化——剥疑问前缀与属性词（「NASA founding year」→「NASA」），中文无空格连写同样覆盖（「周杰伦专辑」→「周杰伦」）。
- **面查意图守卫 + 同构垃圾检测**：「pnpm file: dependency 重装问题」这类长主题句不再被 pypi/models_dev 词面误抢返回垃圾包；单 token 包名垃圾结果不再骗过早停守卫。
- **中文正则词边界修复**（两处同根因）：`\b` 对 CJK 永不成立，「npm安装报错」这类连写意图词失配导致真实点查被误让位——中文备选统一移出词边界组。

### 3. 搜索源利用率

- **知乎三源语义分工**（一个 ZHIHU_ACCESS_SECRET 撬动 10500 次/天）：
  - **站内搜索**（5000/天）：观点/经验/评测 UGC——配额此前按 1000/天误配，用到 20% 就被本地封禁，已对齐；
  - **全网搜索**（5000/天）：中文时事/多域名泛资讯——此前因自适应降权 + 预算截断在自家主域永远轮不上（37 天仅 53 次），已修复防饿死并接入新闻域；
  - **个人数据**（10000/天，新增）：本人创作内容/收藏/关注，`我的回答 点赞最多`、`我的收藏`、`我关注的人` 直接可查——查本人数据用 Access Secret 直调，无需 OAuth。
- **UAPI 聚合搜索重新启用**（免 key，历史 521 次 0% 错误）；**DuckDuckGo 移出兜底链**（错误率 45%、实测 11 秒 0 条），UAPI 顶入。
- **研究采集按子查询语言/学术意图分发**：中英混合研究的引擎参战数 2→13（英文源与 github 等全面参与）；学术查询按《学术检索协议》顺序接入 17 个学术源（Semantic Scholar 起步 → arXiv 补预印本 → openalex/crossref → Google Scholar 兜底）。
- **密钥兼容同步**：`~/.config/argo/env` 在 CLI/MCP 入口单向同步进环境变量（只填缺失、不覆盖已有）——裸 shell、直跑进程、其他 Agent 集成的既有密钥读取方式零改动，未配环境变量的部署也能拿到密钥。

### 4. 新能力

- **zhihu_user 个人数据引擎**（新能力族 personal_data）：创作运营与素材回溯；互补回填排除——通用搜索 combo 永不混入个人收藏。
- **声明式语言分发**：引擎语言能力（langs）进元数据，路由的语言重排/ja-ko 过滤由元数据派生（原四张手写冻结表删除）；`family_candidates(能力族, 语言, 模式)` 单一取源口。新源接入 = 注册 + 声明族与语言一次，全部分发路径自动生效。
- **可达性门（WARN）**：enabled 引擎必须被 ≥1 条分发路径可达（域 combo / 兜底 / 选题 profile / 研究 boost / TF-IDF 语义画像），当前 8 个死源已显形待逐源接线。
- **学术检索协议**（`references/academic-query.md`）：17 学术源查询构造、多库去重、相关性五因子排序、引用网络挖掘、18 条反模式、与证据体系（事实/推断/未知）对齐。
- **配额口径对齐**：zhihu 5000/天、anysearch 2000/天、zhihu_global 5000/天；无限额引擎的计数周期归零（遥测不再永久累计）。
- **小红书 REDSkill 技能检索域**：47650 个技能的全量检索与榜单（数据本地缓存）。

### 5. 修复与加固

- **YAML 同名键静默覆盖**：引擎块内 `timeout` 重复声明导致 6s 硬超时从未生效——新增 `test_config_dup_keys` 门，config 与 specs 全量拒绝重复键。
- **hedged 竞速超时路径丢结果**：恰在末次轮询后完成的线程此前既不入账也不标超时（静默消失）；超时记账由「超时参数×1000」假值改为真实等待时长（遥测诚实化）。
- **跨平台与安全加固**：Windows GBK 编码乱码修复（curl/mcp-jobs/子进程显式 UTF-8）；SSRF 重定向每一跳校验（起始白名单挡不住服务端 302 跳内网）；recompute 沙箱补封 os.open/os.fdopen 与 Path/bytes 开口；任务快照原子写；`--force` link 迁移前加副本软校验。
- **SKILL.md 分层按需读取**：稳态 token 开销 −52%。

## 默认关闭功能的打开方式

- **MCP 14 工具**：默认关闭。DSH 用户在 profile patch 取消 `mcp-argo` 段注释后重启生效；非 DSH 用户见 README「MCP 接入」。
- **原生一等工具**：默认仅 `argo_search`/`argo_fetch`；`nativeTools` 配置可按需启用全部 13 个（`argo_research` 除外——分钟级编排不适合 60s 单发超时）。
- **TinyFish / Firecrawl**：配置 `TINYFISH_API_KEY` / `FIRECRAWL_API_KEY` 即启用（Firecrawl 匿名免费层当前已被上游限制，需注册 key）。
- **recompute 数值重算器**：默认 fail-closed，`--allow-recompute` 或 `ARGO_ALLOW_RECOMPUTE=1` 显式授权。

## 相关依赖

- 无新增强制依赖；Python 3.10+，可选 `yaml/requests`（安装脚本自动选解释器）。
- 引擎密钥统一走 `~/.config/argo/env`（600 权限）或环境变量；zhihu 系四引擎共用 `ZHIHU_ACCESS_SECRET`。
- 已知环境级事实：iTunes cn storefront 接口当前上游返回空（media 域由 musicbrainz 兜底）；Nominatim 在部分网络不可达（geo 域由 wikidata/zh_wikipedia/anysearch 兜底，OSM 超时已收紧至 6s）。
