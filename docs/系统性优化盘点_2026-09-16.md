## 二、MECE 八面盘点

### 1. 数据面（源）
**现状**：232 源，09-16 新增 5 个免密钥国内源实测健康（weibo_hot 283ms / douyin_hot 290ms /
wallstreetcn 339ms / csdn 1108ms / weather_cn 685ms 全过）。
**判断**：规模与质量都在轨；本域缺口已在 09-12 调研登记（TikHub/轻抖待拍板）。
**本面无新提案。**

### 2. 路由面
**现状**：138/0/1 离线矩阵；90 域编译 30ms/进程（已验证无捷径：零纯字面量、
懒编译无收益——典型查询 90/90 域都会被扫）。
**判断**：准确率在轨，成本架构性。提案见第六节「QPP」条。

### 3. 执行面
**现状**：hedged race + 有界并发 + 预算早停，wasted_ms 遥测如实记账。
**判断**：网络墙钟已接近下界。调度器用 `time.time()`（墙钟）计预算——NTP 跳变
理论上会拉长/缩短预算窗；换 `time.monotonic()` 属系统性修正，但触及刚拆分且
满测试的编排热区，**收益不抵搅动**，仅在下次动该文件时顺路改。

### 4. 融合/排序面
**现状**：RRF + 精排熔断 + 去重提前停；排序金标基建已在位（e02bb14）。
**外部发现**（本轮 dogfood 实查）：RRF 调参是 2026 活跃实践区——Google 开发者
社区有「Tuning RRF in Agent Retrieval」专帖，OpenSearch/Redis 均发加权 RRF 实现
文；「源权威加权 RRF」与既有 backlog 的「域信誉层」互为印证，合并跟进。

### 5. 输出面（上下文）
**现状**：agent 档 600 token；timing 默认开（几百字节换自解释瓶颈，划算）。
**判断**：无新提案。`elapsed_ms` 在 agent 档被剥掉——排查延迟时用 `--explain-timing`
自答，口径已闭环。

### 6. 通道面
**现状**：CLI 冷启动 ~250ms 固定开销（架构性）；MCP 常驻连接已存在且被 DSH
原生工具复用。`logging` 导入链在 py3.14 带出 ~24ms（traceback→_colorize→dataclasses），
14 个模块引用，省它要全链改惰性——**不划算，明示放弃**。
**判断**：CLI 重度场景的正解是走 MCP 面，无需新代码。

### 7. 文档面
**现状**：SKILL.md 引用纪律已立；usage.md 证据流程/answer 语料实测表已补。
**抽查**：SKILL.md 上下文纪律条与实测一致（agent 档 2.4KB）。

### 8. 测试面（本轮主发现）
**现状**：2240 项，门禁文化成熟（变异验证、跨解释器语法门、静态缺陷门）。
**缺口（本轮盘点实数）**：116 个脚本中 17 个测试零引用，甄别后——
  - research 管线族（research_cli/research_expand/research_strategy/social_research，
    ≈700 行）**零直测**：仅靠 local_bridge 间接覆盖。已补冒烟门（导入性 + 入口
    存在性 + --help 退出码）。
  - 自检工具类（regression_p0p1/ab_eval_p0p1/lang_matrix_probe/mcp_diag/
    sync_installs）本身是测试工具，无需覆盖。
  - screenshot/search_types 薄壳，风险低，不补。
